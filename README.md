# BSL Forge

**Разработка на 1С:Предприятии 8 в VS Code и 1C:EDT — самостоятельно или с ИИ-агентом.**

Поправьте модуль в VS Code и нажмите `Ctrl+Alt+U`. BSL Forge загрузит правку в выбранную базу, запустит синтаксический контроль и обновит конфигурацию БД. Если 1С найдёт ошибку, щёлкните по ней в панели **«Проблемы»** — откроется нужная строка модуля.

Ту же задачу можно поручить ИИ-агенту. Он видит реквизиты и методы **вашей** конфигурации, меняет обычные файлы проекта и получает результат проверки от 1С. Перед загрузкой вы видите, **что изменилось и в какую базу это попадёт**. Без вашего «Разрешить» агент ничего не запишет в базу. В боевую базу он не пишет вообще.

## Быстрый старт

Для **VS Code и VSCodium** нужны Windows 10/11, платформа 1С:Предприятие 8.3.x или 8.5 и база разработки или тестовая копия. Подходят файловые и серверные базы. Node.js, npm и отдельный MCP-сервер устанавливать не нужно. ИИ-агент для первых шагов тоже не нужен.

1. **Откройте папку проекта.** Подойдёт папка с выгрузкой конфигурации или пустая папка. Нажмите на значок наковальни слева. В блоке **«Начало работы»** выберите **«Настроить в один клик»**: мастер проверит Git, подсветку BSL и платформу 1С. Саму платформу нужно установить отдельно.
2. **Свяжите проект с базой.** Нажмите `Ctrl+Shift+P` → **«BSL Forge: Создать проект»**. Выберите копию базы и проверьте её роль: *разработка* или *тестовая*. Если исходники уже есть, плагин найдёт их. Если папка пуста, он предложит выгрузить конфигурацию из базы. Отметьте нужные расширения. Настройки сохранятся в `.forge/forge.json`.
3. **Внесите небольшую правку.** Если используете Git, сначала сделайте коммит исходной выгрузки: так будет видно, что поменялось. Затем откройте знакомый модуль `.bsl`, внесите изменение и сохраните файл.
4. **Нажмите `Ctrl+Alt+U` — «Применить».** При первой загрузке плагин предложит загрузить всё. Проверьте название базы и подтвердите операцию. Результат появится в уведомлении, ошибки — в **«Проблемах»**, а запись об операции останется в **«Истории»**. Чтобы проверить поведение кода, поставьте точку останова (`F9`) и запустите 1С с отладкой (`F5`).

**Можно без Git.** С Git после первой загрузки «Применить» загружает только изменения. Если отключить Git в **BSL Forge › Git**, загрузка каждый раз будет полной. При первой выгрузке большой УТ, КА или ERP мастер также предложит **«Выгрузить без git»**, чтобы не ждать индексации десятков тысяч файлов.

## Подключение агента

В VS Code и VSCodium агент обращается к плагину через **MCP** — так он получает структуру объектов, запускает проверку и читает ошибки 1С. Начните с вопроса, для которого не нужна запись: **«Какая база сейчас выбрана и какие расширения есть в проекте?»**

| Если вы используете | Что сделать |
| :--- | :--- |
| **Claude Code в VS Code** | Установите Claude Code и войдите в аккаунт. Выполните **«BSL Forge: Подключить ИИ-агента (MCP)»** → **Claude Code**. Откройте Claude в папке проекта, подтвердите доверие к `onec-forge`. Команда `/mcp` должна показать статус `connected`. Настройки — в `.mcp.json`. |
| **GigaCode в VSCodium или VS Code** | Установите GigaCode, войдите в аккаунт и включите в чате **режим агента**. В той же команде подключения отметьте **GigaCode**, затем перезапустите его или редактор. Настройки — в `.gigacode_vsc/gigacode.jsonc`. В корпоративной версии MCP должен разрешить администратор. |
| **SourceCraft Code Assistant** | Выберите **SourceCraft Code Assistant** в мастере. Плагин запишет настройки в `.codeassistant/mcp.json`. Доступно и в редакции РФ. |
| **Другой агент** | В обычной редакции мастер также настраивает Cursor, Codex и Kimi Code. Copilot в VS Code видит инструменты сам в режиме «Агент». Для другого MCP-клиента выберите **«Другой агент»** и вставьте предложенные настройки в его конфигурацию. Так можно подключить и клиента с локальной моделью. |

Настройки запуска MCP содержат пути вашего компьютера и исключаются из общего репозитория. Если пользователю 1С нужен пароль, для агента задайте переменную окружения `FORGE_PASSWORD`, а не поле в файле проекта.

**Дайте агенту инструкции по 1С.** Команда **«BSL Forge: Установить скиллы 1С для ИИ-агента»** добавляет в проект набор из 72 скиллов: от запросов и стандартов ИТС до расширений, форм, СКД и ролей. Для Claude Code это `.claude/skills`, в редакции РФ — `.agents/skills`. Эти папки, в отличие от локальных настроек запуска, можно хранить в Git. В команде **«BSL Forge: Выбрать скиллы»** оставьте только нужные.

### Первая задача: небольшая правка в расширении

Укажите своё расширение и модуль. Например, для демонстрационного проекта задача выглядит так:

> В общем модуле `ft_Тест` расширения `ForgeTest` добавь функцию `КомментарийДляСклада`. Если комментарий пустой, верни «Без комментария», иначе убери пробелы по краям. Покажи изменения, примени их в базу разработки и проверь синтаксис.

Сначала изменится файл в проекте — его уже можно открыть и посмотреть. Когда агент запросит загрузку, **сам редактор** покажет название базы, состав операции и сведения о резервной копии. Нажмите **«Разрешить»** или отмените: при отказе правка останется в файле, но не попадёт в базу. Синтаксический контроль проверяет код; чтобы проверить поведение функции, попросите агента отдельно написать и запустить тест.

## Что ещё можно сделать в VS Code

| Задача | С чего начать |
| :--- | :--- |
| **Найти код, не зная имени метода** | Введите «где считается скидка по карте» в поиске по смыслу. Поиск работает локально. Если знаете объект, команда **«Где используется»** покажет ссылки на него, а для регистра — ещё и кто пишет движения. |
| **Разобраться в незнакомой конфигурации** | В дереве **«Конфигурация 1С»** найдите объект по имени или синониму. Откройте модуль, права роли, запрос набора СКД или печатный макет. В палитре можно изменить свойства и тип реквизита; при сужении типа плагин попросит подтверждение. |
| **Понять, что заденет правка** | Откройте карту конфигурации: на ней видны пути между объектами, частота правок и ошибки загрузки. Карту можно сохранить в HTML, а ER-диаграмму объекта — в Mermaid, Draw.io, SVG или PNG. Агент получает те же связи короткой сводкой, а не перечитывает всю XML-выгрузку. |
| **Переименовать объект** | Сначала посмотрите список замен. Плагин обновит имя и ссылки в коде, запросах, ролях, подсистемах и расширениях. UUID сохранится: для 1С это тот же объект, а не удаление старого и создание нового. |
| **Написать и проверить запрос** | Поставьте курсор в строку запроса и откройте **«Конструктор запроса…»**. Дерево таблиц берётся из исходников. Для проверки на данных откройте консоль, задайте параметры и нажмите `Ctrl+Enter`. Консоль читает данные через мост; результат можно скопировать в Excel. |
| **Разобрать ошибку пользователя** | Передайте команде **«Разобрать ошибку пользователя»** текст сообщения или ZIP-отчёт из 1С. Причины появятся в «Проблемах» со ссылками на модули. Если сообщения нет, посмотрите журнал регистрации за нужный период: ошибки сгруппированы по месту в коде. |
| **Проверить сценарий в 1С** | Откройте `.feature` в панели **«Тестирование»** и запустите файл или один сценарий Vanessa Automation. Если шаг упал, ошибка появится на его строке. Результаты сохраняются в формате Allure для CI. На боевой базе тесты не запускаются. |
| **Подготовить выпуск** | Сравните метаданные с базой, коммитом или веткой: вместо XML увидите, например, какой реквизит добавили или где сократили длину строки. Если работаете с хранилищем 1С, захват объединит версию коллеги с вашей; неразрешённый конфликт остановит загрузку. Для выпуска поставьте метку и соберите `.cf` или `.cfe`. |

## Мост к живой базе

Исходники отвечают на вопрос «какие у документа реквизиты?». Для вопроса «почему сегодня не провёлся заказ?» часто нужны **данные самой базы**. Откройте в ней обработку `ForgeBridge.epf`: консоль запросов и агент смогут читать журнал регистрации, выполнять запросы, проверять права и находить ссылки в пределах прав пользователя 1С.

Мост сам выбирает канал: HTTP, если соединение доступно, иначе — обмен через папку. У клиента по RDP достаточно разрешить перенаправление дисков: интернет на сервере 1С не нужен. На панели **«Действия»** видно, какая база на связи. У каждой базы свой канал, а привязка к проекту не даёт соседнему окну редактора работать с чужой базой.

## Как защищены базы и данные

- **Роли баз.** Укажите `dev`, `test` или `prod`. Агенту запись в `prod` запрещена. Для ручной записи в боевую базу нужно ввести её название; без резервной копии запись не начнётся.
- **Проверка до загрузки.** Плагин остановится, если выгрузка повреждена, исчез объект или реквизит либо сузился тип. Вы увидите, какие данные затрагивает изменение, до обновления БД. Для типового объекта «на замке» плагин предложит перенести поддерживаемые правки в расширение; то, что не удалось перенести автоматически, не отбрасывается.
- **Копии.** Для файловой базы разработки копия `.dt` по умолчанию создаётся раз в день, для боевой — перед каждой записью. У серверных баз разработки и тестирования автоматическая `.dt` по умолчанию отключена: предусмотрите копирование средствами СУБД. Периодичность, папка и хранение копий — в **BSL Forge › Backup**.
- **Пользователи в базе.** Когда платформа допускает динамическое обновление, пользователи продолжают работать. Если изменению структуры нужен монопольный доступ, плагин покажет сеансы. Отключение выбранных пользователей требует отдельного подтверждения.
- **Данные в ответах агенту.** Режим **«Данные не покидают контур»** (`"privacy": "codeOnly"` в `.forge/forge.json`) маскирует значения в результатах запросов и журнале, заменяет имена пользователей и запрещает снимки форм. Код и метаданные остаются видны агенту. Это фильтр ответов инструментов, а не гарантия соответствия 152-ФЗ: для персональных данных учитывайте также размещение модели и то, что вы сами отправляете в чат.

## Плагин для EDT

Если ваш основной проект уже в **1C:EDT 2026.2**, для работы с агентом не нужно переносить его в VS Code. Установите **Node.js 20+** и подключите хотя бы один движок чата.

1. В EDT откройте **Справка → Установить новое ПО… → Добавить…**. В поле **«Расположение»** вставьте:
   ```text
   jar:https://unikr-pro.ru/assets/files/bsl-forge-edt.zip!/
   ```
2. Отметьте **BSL Forge**, примите лицензию и перезапустите EDT.
3. Откройте панель кнопкой с огоньком или `Ctrl+Alt+F`. В **«Настройки → Кто отвечает в чате»** выберите движок: например, Claude Code, Codex, GigaChat, YandexGPT, Cloud.ru или локальную модель Ollama.
4. Выделите фрагмент модуля и нажмите `Ctrl+Alt+A`. Спросите, что делает код, или попросите исправить замечание EDT. После ответа откройте **карточку правки**: в ней видны изменённые строки, число ошибок до и после и кнопка отката. Можно отменить один файл или все изменения сразу.

Агент читает метаданные `.mdo`, а в модуле расширения учитывает его префикс и основную конфигурацию. Если команде нужны оба формата, на панели «Действия» в VS Code есть **«EDT → Конфигуратор»** и **«Конфигуратор → EDT»**. Основная конфигурация **и расширения** переводятся в обе стороны; нужен установленный `1cedtcli`.

## Командная работа

**Задачи проекта** — это Markdown-файлы `tasks/*.md` в репозитории. Одна и та же карточка открывается в VS Code, EDT и на GitHub: описание, исполнитель, срок, объекты 1С и связанные коммиты. В `docs/1c/` команда и агент ведут паспорт проекта и журнал доработок. По итогам задачи можно подготовить заметку «Что нового» с названиями полей и кнопок из программы, а для передачи проекта — паспорт доработок с расширениями, интеграциями и отличиями от типовой.

**Доска «Задачи агентов»** нужна для параллельной работы. Попросите ведущего агента раздать задачи исполнителям: разные объекты можно менять одновременно, а задачи с общим модулем или формой пойдут по очереди. В панели видны ход работы и ошибки; при необходимости можно остановить план. Загрузка в базу — одна, после завершения задач.

**«Команда агентов: архитектор, исполнители, ревьюер»** — отдельный сценарий обычной редакции. В VS Code откройте одноимённую команду через `Ctrl+Shift+P`, в EDT — **BSL Forge → Команда агентов**. Опишите задачу, выберите **«Составить план»**, проверьте его и нажмите **«Утвердить план и начать»**. После ревью прочитайте отчёт. Утверждение плана **не разрешает запись в базу**: в VS Code для неё будет отдельный запрос, в EDT результат останется в исходниках.

## Возможности Pro

Загрузка и проверка, отладчик, тесты Vanessa, карта конфигурации, подключение агента и скиллы входят в бесплатную версию. **Pro** открывается после входа в аккаунт BSL Forge с активной подпиской.

| Инструмент | Когда пригодится |
| :--- | :--- |
| **Ревью и стандарты 1С** | При сохранении видны нарушения, внесённые вашей правкой, а не весь старый код. Доступны 85 правил ИТС, ссылки на стандарты и быстрые исправления (`Ctrl+.`). Ревью можно запускать перед коммитом, в карточке правки EDT или в CI с отчётом SARIF / GitLab Code Quality. |
| **Превью и редактор управляемых форм** | Откройте `Form.xml`, переставьте поля мышью или попросите агента: «Добавь таблицу товаров и кнопку “Заполнить”». Видны изменения свойств, колонок, команд и обработчиков. Пути к данным проверяются по метаданным. |
| **Доктор производительности** | Повторите медленное действие и разберите техжурнал. Плагин покажет запросы в циклах, тяжёлые запросы, блокировки и места вызовов в коде. После исправления можно сравнить замеры «до» и «после». |
| **Трасса** | Нажмите «Начать запись», выполните действие в 1С и остановите запись. В редакторе подсветятся выполненные строки; рядом будут число вызовов, затраченное время и обращения к серверу. |
| **Проверка расширения перед обновлением типовой** | Сравните расширение с новой версией из `.cf`, папки выгрузки или ветки Git. Плагин найдёт пропавшие объекты и изменённые методы, предложит обновить совместимые перехватчики и отдельно покажет конфликты. Рабочая база не меняется. |
| **Дополнительные инструменты моста** | Посмотрите, какие объекты занимают место и какому объекту принадлежит таблица СУБД. Для выполнения кода через мост нужно отдельное нажатие **«Выполнить» в окне 1С**. В режиме проверки транзакция откатывается. |

## Если что-то не работает

| Что вы видите | Что проверить |
| :--- | :--- |
| Агент не видит `onec-forge` | Откройте именно папку проекта, повторите подключение MCP и перезапустите агента. Для Claude проверьте `/mcp`, для GigaCode — режим агента и разрешение на MCP в корпоративных настройках. |
| «Не у кого спросить подтверждение» | Откройте проект в VS Code или VSCodium с включённым BSL Forge: запрос должен появиться в редакторе. Сообщение «разрешаю» в чате его не заменяет. |
| «Нужна полная загрузка» | Для новой базы это ожидаемо. Убедитесь, что выбрана нужная копия, затем нажмите **«Применить» → «Загрузить всё»**. Для базы, привязанной к хранилищу, используйте **«Обновить из хранилища»**. |
| Платформа не найдена | Проверьте установку 1С и укажите папку поиска в `onecForge.platformRoots` или версию в `onecForge.platformVersion`. |

Не помогло? Выполните **«BSL Forge: Сообщить об ошибке»**. Перед отправкой можно прочитать весь отчёт. Вопросы и предложения: <unikr_1c@mail.ru>.
